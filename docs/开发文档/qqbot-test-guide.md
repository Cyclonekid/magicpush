## 一、测试前准备

### 1.1 前置条件检查清单

在开始测试之前，请确保以下准备工作已完成：

#### 必须具备

- [ ] **QQ 开放平台账号**
  - 访问地址：https://q.qq.com/
  - 支持企业或个人主体注册
  
- [ ] **已创建 QQ 机器人应用**
  - 获取到 AppID 和 AppSecret
  - 已完成基础信息设置（头像、名称等）
  
- [ ] **MagicPush 服务运行正常**
  - 后端服务已启动（默认端口 3000）
  - 数据库连接正常
  - 可以访问管理后台

- [ ] **网络连通性**
  - 服务器能访问 `https://bots.qq.com` （获取Token）
  - 服务器能访问 `https://api.sgroup.qq.com` 或沙箱环境
  - 如需代理，请提前配置好代理地址

#### 推荐准备

- [ ] **QQ 客户端**（手机/电脑）
  - 用于接收和查看测试消息
  
- [ ] **测试群/频道**
  - 一个用于群聊模式测试的 QQ 群（机器人已加入）
  - 一个用于子频道模式测试的 QQ 频道（机器人已添加）
  
- [ ] **测试用户**
  - 用于 C2C 单聊模式测试的用户账号
  - 需要主动给机器人发送过至少一条消息

---

### 1.2 环境选择说明

| 环境 | API 地址 | 适用场景 | 说明 |
|------|---------|---------|------|
| **沙箱环境** | `https://sandbox.api.sgroup.qq.com` | 开发测试 | 成员数 ≤ 20人，无需IP白名单 |
| **正式环境** | `https://api.sgroup.qq.com` | 生产使用 | 需配置IP白名单，机器人需已发布 |

> 📌 **推荐**：首次测试使用**沙箱环境**，验证通过后再切换至正式环境。

#### 切换环境方式

在 MagicPush 渠道配置中，当前不支持直接选择沙箱/正式环境。如需在沙箱测试：

1. 修改代码中的 baseUrl（临时方案）：
   ```javascript
   // qqbot.channel.js 构造函数中
   const client = new QqbotClient({
     appId: this.appId,
     clientSecret: this.clientSecret,
     proxyUrl: this.proxyUrl,
     // baseUrl: 'https://sandbox.api.sgroup.qq.com' // 取消注释启用沙箱
   });
   ```

2. 或者在创建渠道时，通过配置字段传递（如果后续支持）

> ⚠️ **注意**：当前实现默认使用正式环境。建议先确保机器人已发布或使用沙箱环境。

---

### 1.3 IP 白名单配置（正式环境必需）

如果是正式环境，必须配置服务器 IP 白名单：

1. 登录 [QQ 开放平台](https://q.qq.com/)
2. 进入机器人管理页面
3. 点击机器人 → 「开发设置」→「安全设置」
4. 在「IP 白名单」中添加 MagicPush 服务器的公网 IP
   - 可通过命令获取：`curl ifconfig.me`
   
> ⚠️ **重要**：未配置白名单将导致所有API调用失败！

## 二、功能测试用例

### 测试用例 1: 群聊消息推送 (group)

**目标**: 验证群聊模式下消息能否成功发送到指定 QQ 群

#### 步骤

1. 在 MagicPush 管理后台，点击「绑定渠道」
2. 选择渠道类型：「QQ机器人」
3. 填写配置信息：
   ```
   AppID: <你的机器人AppID>
   AppSecret: <你的机器人AppSecret>
   推送场景: group（群聊消息）
   目标 ID: <群的group_openid>
   代理地址: （可选，根据网络情况填写）
   ```
4. 渠道名称填入：「QQ群聊测试」
5. 点击保存
6. 在渠道卡片右侧下拉菜单中，点击「测试」

#### 预期结果

✅ **成功标准**:
- 测试返回"测试消息发送成功"
- QQ 群中出现一条来自机器人的测试消息："测试消息\n\n这是一条来自魔法推送的测试消息"

❌ **失败排查**:
- 如果返回错误码 `304002`: 机器人未加入该群，或群ID不正确
- 如果返回错误码 `10001`: 检查AppID/AppSecret是否正确
- 如果超时: 检查网络/代理配置

---

### 测试用例 2: 单聊/C2C消息推送 (c2c)

**目标**: 验证C2C模式下消息能否成功发送到指定用户的消息列表

#### 前置步骤（获取 user_openid）

1. 使用测试用户的 QQ 号码
2. 在 QQ 中找到机器人，并**给机器人发送任意一条消息**
3. 这一步是为了让系统记录下该用户的 openid

> ⚠️ **注意**: 当前 MagicPush 不支持自动从事件中收集 openid，你需要通过其他方式（如查看日志、调用API）获取该用户的 openid。后续版本可能会集成 WebSocket 来自动处理。

#### 测试步骤

1. 创建新渠道（或编辑现有渠道），选择：
   ```
   推送场景: c2c（单聊消息）
   目标 ID: <测试用户的user_openid>
   ```
2. 其他配置与测试用例1相同
3. 点击「测试」

#### 预期结果

✅ **成功标准**:
- 测试返回"测试消息发送成功"
- 用户的消息列表中收到来自机器人的消息

❌ **失败排查**:
- 错误码 `304003`: 用户不存在或openid错误
- 错误码 `53400`: 无法建立会话，用户可能未主动发过消息给机器人

---

### 测试用例 3: 子频道消息推送 (channel)

**目标**: 验证子频道模式下消息能否成功发送到 QQ 频道子频道

#### 前置步骤

1. 将机器人添加到目标 QQ 频道
2. 在频道中创建一个子频道（如果没有的话）
3. 获取子频道的 channel_id（右键子频道 → 复制ID）

#### 测试步骤

1. 配置渠道：
   ```
   推送场景: channel（子频道消息）
   目标 ID: <子频道channel_id>
   ```
2. 点击「测试」

#### 预期结果

✅ **成功标准**:
- 测试消息出现在指定的子频道中
- 支持 Markdown 渲染（如果测试时type为markdown）

❌ **失败排查**:
- 错误码 `304001`: 频道不存在或机器人未加入
- 错误码 `304004`: 子频道不存在

---

### 测试用例 4: 私信消息推送 (dms) - 旧版方式

**目标**: 验证私信模式下消息能否成功发送

#### 前置步骤

同测试用例2，需要获取用户的 openid，且用户需主动给机器人发过消息。

#### 测试步骤

1. 配置渠道：
   ```
   推送场景: dms（私信消息）
   目标 ID: <用户openid>
   来源频道 ID: （可选，通常留空即可）
   ```
2. 点击「测试」

#### 预期结果

✅ **成功标准**:
- 用户收到机器人的私信消息
- 注意：私信**不支持 Markdown**，会自动转为纯文本

❌ **失败排查**:
- 错误码 `53400`: 无法创建私信会话
- 错误码 `53401`: 私信功能未开通

---

### 测试用例 5: Markdown 消息格式

**目标**: 验证群聊/C2C/子频道模式下的 Markdown 渲染效果

#### 测试步骤

1. 使用群聊/单聊/子频道任一模式创建渠道
2. 通过 API 发送 Markdown 格式消息：

```bash
curl -X POST http://<服务器IP>:3000/api/push/<渠道ID> \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的APIToken>" \
  -d '{
    "title": "🚨 系统告警",
    "content": "**告警级别**：高\n\n> 服务器：192.168.1.100\n> CPU使用率：95%\n> 时间：2026-07-02 21:30\n\n请立即处理！",
    "type": "markdown"
  }'
```

#### 预期结果

✅ **成功标准**:
- 消息正确渲染为 Markdown 格式
- 加粗、引用等语法生效

❌ **预期行为**:
- 如果是私信模式(dms)，Markdown会被转为纯文本显示

## 三、边界测试

### 3.1 消息长度限制测试

**目标**: 验证超长消息的截断处理

#### 测试方法

生成一个超过 5000 字符的长消息进行推送：

```bash
# 生成6000字符的测试内容
long_content=$(python3 -c "print('测试内容 ' * 750)")
curl -X POST http://<服务器IP>:3000/api/push/<渠道ID> \
  -H "Content-Type: application/json" \
  -d "{\"content\": \"$long_content\", \"type\": \"text\"}"
```

#### 预期结果

- ✅ 消息成功发送
- ✅ 消息被截断为 5000 字符
- ✅ 服务端日志出现警告：`[QQBot] 消息已截断: 6000 → 5000 字符`

---

### 3.2 特殊字符测试

**目标**: 验证特殊字符的处理能力

#### 测试内容

包含以下特殊字符的消息：
```json
{
  "content": "特殊字符测试：<>&\"'\\n换行\\t制表符",
  "type": "text"
}
```

#### 预期结果

- ✅ 消息正常发送，无乱码
- ✅ HTML/Markdown 特殊字符正确转义

---

### 3.3 Token 过期刷新测试

**目标**: 验证 Access Token 自动刷新机制

#### 测试方法

1. 清除服务端 Token 缓存（重启服务）
2. 连续发送两条消息，间隔 > 0秒
3. 观察日志输出

#### 预期结果

- ✅ 第一条消息触发 Token 获取
- ✅ 日志输出：`QQBot 正在获取新 Access Token`
- ✅ 第二条消息命中缓存（无重复获取）
- ✅ 日志输出：无新的Token获取日志

---

### 3.4 网络异常测试

**目标**: 验证网络故障时的错误处理

#### 测试场景

1. **断开代理**（如果使用了代理）
   - 预期：返回网络错误，提示检查代理
   
2. **错误的 AppSecret**
   - 预期：返回明确的错误提示，而非崩溃
   
3. **不存在的目标ID**
   - 预期：返回具体的错误码（304002/304003等）

---

### 3.5 并发测试（可选）

**目标**: 高并发场景下的稳定性

#### 测试方法

使用脚本快速发送多条消息：

```bash
for i in {1..10}; do
  curl -X POST http://<服务器IP>:3000/api/push/<渠道ID> \
    -H "Content-Type: application/json" \
    -d "{\"title\": \"并发测试 $i\", \"content\": \"第 $i 条消息\", \"type\": \"text\"}" &
done
wait
```

#### 预期结果

- ✅ 所有消息最终都能发送成功
- ✅ 无 Token 冲突或竞态问题（Node.js单线程天然避免）
- ✅ 消息序号(msg_seq)递增正确

## 六、常见测试问题排查

### 问题 1: 所有请求都报"token无效"

**可能原因**:
1. AppSecret 填写错误（最常见）
2. 机器人未发布/审核未通过
3. IP 白名单未配置（正式环境）

**解决步骤**:
1. 从 QQ 开放平台重新复制 AppSecret
2. 确认机器人状态为"已上线"
3. 检查并添加服务器 IP 到白名单
4. 查看服务端详细日志

---

### 问题 2: 能获取Token但发送消息失败

**可能原因**:
1. 目标ID格式错误
2. 机器人未加入群/频道
3. 权限不足

**解决步骤**:
1. 确认目标ID类型正确（group_openid vs channel_id vs user_openid）
2. 群聊：确认机器人已在群内
3. 子频道：确认机器人已被添加到频道
4. 单聊：确认用户已主动给机器人发过消息
5. 检查错误码，参考 `_translateError()` 的映射表

---

### 问题 3: 消息发送成功但收不到

**可能原因**:
1. 用户屏蔽了机器人消息
2. 消息被 QQ 风控拦截（频率过高/敏感词）
3. 机器人被禁用

**解决步骤**:
1. 检查 QQ 客户端是否有"消息免打扰"或屏蔽设置
2. 降低发送频率，避免触发风控
3. 登录 QQ 开放平台检查机器人状态
4. 尝试更换测试内容（避免敏感词汇）

---

### 问题 4: 代理相关错误

**典型错误**:
- `ECONNREFUSED`: 代理软件未启动
- `ETIMEDOUT`: 代理不可达或配置错误
- `socket hang up`: 代理断开连接

**解决步骤**:
1. 确认代理软件正在运行
2. 确认代理地址正确（端口、协议）
3. 测试代理可用性：`curl -x http://127.0.0.1:7890 https://api.sgroup.qq.com`
4. 确保代理允许局域网连接（LAN）
